## recon-pipeline 流水线化改造 (端到端自动侦察)

### 需求
用户给 URL → 自动判断是 LLM Web App (需认证/跨域/同域/二次验证) 还是模型平台 (OpenAI/Ollama/LM Studio) → 自动跑全下游侦察 (agent/mcp/rag/embedding/llm...) → 标准报告供下游消费。改造为解耦流水线模式 + config/ 集中参数 + .env 必改变量。

### 新增目录结构
- `pipeline/` — 解耦阶段层 (不修改 core/, 仅复用)
  - `pipeline/models.py` — 阶段间解耦数据契约 (PipelineContext/TargetClassification/AuthDecision/StageResult)
  - `pipeline/stages/base.py` — PipelineStage ABC (execute 统一计时+异常隔离)
  - `pipeline/stages/classify_stage.py` — 阶段1: 目标分类 (vendor识别 + 浏览器认证拓扑探测 + 二次验证检测)
  - `pipeline/stages/auth_stage.py` — 阶段2: 认证决策 (NoneAuth/APIKey/Playwright 同域·跨域·二次验证)
  - `pipeline/stages/recon_stage.py` — 阶段3: 端到端侦察编排 (按分类自动选探针 → ReconOrchestrator)
  - `pipeline/stages/export_stage.py` — 阶段4: 标准报告导出 (json/pyrit/garak)
  - `pipeline/registry.py` — 阶段注册表 (解耦 runner 与具体阶段)
  - `pipeline/runner.py` — PipelineRunner (顺序执行 + StageResult 错误隔离)
  - `pipeline/context_loader.py` — 从 .env + config/ 加载 (必改变量走 .env)

### 配置层
- `config/settings.py` — 集中最优默认参数 (HTTP/Probe/Auth/Classify/PortScan/Pipeline)
- `config/default.yaml` — 配置模板参考
- `.env.example` / `.env` — 必改变量 (TARGET_URL/API_KEY/ORG_DOMAINS/AUTH_* 等)
- `core/config.py` — 从 .env + config/ 加载配置单例

### 关键设计决策
- **不改动 core/**: pipeline/ 仅复用 core 的 TargetUrlClassifier / AuthProbe / AuthStrategy / ReconOrchestrator / exporters / GuardrailPolicy
- **阶段仅通过 PipelineContext 交换数据**: 实现解耦
- **StageResult 错误隔离**: 单阶段失败不阻断整条流水线
- **分类逻辑修正**: TargetUrlClassifier 的 primary_category 是 mcp/agent/rag/llm/auth/upload, 非 platform/webapp; 模型平台判定改为 vendor 指纹优先 (主机/端口 > 通用 /v1/ 路径)
- **认证决策**: 模型平台+Key→APIKeyAuth; WebApp+same_domain→PlaywrightAuth; cross_domain→PlaywrightAuth+IdP; 二次验证→needs_human=True
