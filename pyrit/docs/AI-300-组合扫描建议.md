## 二、为什么要做组合扫描？

单策略侦察的目的是**发现模型防御弱点**。但生产环境中，现代 LLM 的防御通常由多层过滤器构成：

```text
输入层：关键词 / 意图分类 / 角色检测
处理层：系统提示 / 安全护栏（RAG 层）
输出层：拒绝模板 / 免责声明检测
```

组合扫描的核心逻辑是：

```text
组合成功率 ≈ 越狱层成功率 × 混淆层成功率 × 载荷隐藏成功率
```

当前已经找到越狱层（Academic/Contextual）和载荷类型（SQLi、工具边界）的突破口，下一步应重点验证以下组合：

1. **Academic/Contextual + 编码混淆**：看学术包装能否掩护编码载荷绕过输入层。
2. **Academic/Contextual + 多轮 Crescendo**：看单轮成功策略能否在更严格的目标上通过多轮渐进式引导提升成功率。
3. **Academic/Contextual + 工具边界**：将 PROBE_05 的成功复制到 CAP 工具调用用例。
4. **Base64/ZeroWidth + 学术前缀**：用学术前缀降低编码载荷的恶意意图检测分数。

## 三、推荐组合扫描矩阵（优先级排序）

### 组合 1：学术框架 + 编码混淆（高优先级）

目标：复用 PROBE_02 的成功学术包装，掩护编码后的恶意载荷。

| 组合名 | 第一层 | 第二层 | 目标 PROBE/CAP |
|--------|--------|--------|----------------|
| Academic + Base64 | `Academic_Research` | `Base64Converter` | PROBE_02, PROBE_03, sqli_auth_bypass |
| Academic + ZeroWidth | `Academic_Research` | `ZeroWidthConverter` | PROBE_02, PROBE_03, sys_prompt_leak |
| Contextual + Base64 | `Contextual_Priming` | `Base64Converter` | PROBE_02, PROBE_05, reverse_shell |
| Contextual + ROT13 | `Contextual_Priming` | `ROT13Converter` | PROBE_02, PROBE_05, password_cracking |

预期：如果模型在学术角色下对编码内容的警惕性降低，组合成功率可能高于单策略。

### 组合 2：学术框架 + 多轮 Crescendo（最高优先级）

目标：把单轮成功策略迁移到多轮，以攻克更严格的 CAP 用例。

| 组合名 | 单轮种子 | 多轮引擎 | 目标用例 |
|--------|----------|----------|----------|
| Crescendo-Academic | `Academic_Research` | `CrescendoOrchestrator` | reverse_shell, phishing_email, sqli_auth_bypass |
| Crescendo-Contextual | `Contextual_Priming` | `CrescendoOrchestrator` | reverse_shell, buffer_overflow, tool_boundary |

预期：Crescendo 的渐进式引导 + 学术包装，是当前最有可能攻破多轮严格目标的组合。

### 组合 3：学术框架 + 角色扮演/直接注入（中优先级）

目标：用学术包装为角色扮演或系统提示注入提供合法性外衣。

| 组合名 | 第一层 | 第二层 | 目标用例 |
|--------|--------|--------|----------|
| Academic + Roleplay | `Academic_Research` | `Roleplay_Jailbreak` | PROBE_01, sys_prompt_extraction |
| Contextual + Suffix | `Contextual_Priming` | `Suffix_Injection` | PROBE_04, sys_prompt_leak |
| Academic + Direct_Extract | `Academic_Research` | `Direct_Extract` | PROBE_04, sys_prompt_leak |

### 组合 4：双学术包装叠加（测试冗余性）

目标：验证是否双重学术框架可以进一步降低防御。

| 组合名 | 第一层 | 第二层 | 目标用例 |
|--------|--------|--------|----------|
| Double Academic | `Academic_Research` | `Contextual_Priming` | PROBE_02, PROBE_05, 全部 CAP 用例 |

### 5.3 批量组合脚本

创建 `scripts/combo_scan_probe.ps1`：

```powershell
$combos = @(
    @{name="Academic_Base64"; first="airt.jailbreak"; first_args="{strategies:['prompt_sending']}"; second="garak.encoding"; second_args="{strategies:['base64']}"},
    @{name="Academic_ZeroWidth"; first="airt.jailbreak"; first_args="{strategies:['prompt_sending']}"; second="garak.encoding"; second_args="{strategies:['zero_width']}"},
    @{name="Contextual_Base64"; first="airt.jailbreak"; first_args="{strategies:['role_play']}"; second="garak.encoding"; second_args="{strategies:['base64']}"},
    @{name="Contextual_ROT13"; first="airt.jailbreak"; first_args="{strategies:['role_play']}"; second="garak.encoding"; second_args="{strategies:['rot13']}"}
)

foreach ($c in $combos) {
    $outDir = "d:/文档/codes/AI-300/results/combo_$($c.name)"
    New-Item -ItemType Directory -Force -Path $outDir | Out-Null

    pyrit_scan `
      --target openai `
      --target-args "{deployment_name:'gpt-4o',api_key:'$env:OPENAI_API_KEY'}" `
      --scenario $($c.second) `
      --scenario-kwargs "$($c.second_args)" `
      --initializer $($c.first) `
      --initializer-kwargs "$($c.first_args)" `
      --dataset-path "d:/文档/codes/AI-300/data/multi_stage_capstone_cases_cn.json" `
      --output-dir $outDir
}
```

运行：

```powershell
.\scripts\combo_scan_probe.ps1
```

## 六、组合扫描后的分析指标

组合扫描完成后，建议关注以下指标：

| 指标 | 计算方式 | 说明 |
|------|----------|------|
| 组合绝对增益 | `combo_rate - max(single_rate_a, single_rate_b)` | 组合是否比单策略更好 |
| 组合相对增益 | `(combo_rate - max_single) / max_single × 100%` | 提升百分比 |
| 跨场景迁移率 | `场景 B 成功组合数 / 场景 A 成功组合数` | 判断是否可迁移到 CAP |
| 多轮成功率 | `Crescendo 成功数 / Crescendo 总尝试数` | 严格目标下是否仍能突破 |
| 新的热力图空白区 | 矩阵中新出现的 100% 单元格 | 发现新的脆弱点 |

## 九、风险与注意事项

1. **过拟合风险**：当前仅 10 次攻击，3 次成功。组合扫描可能放大统计波动，建议每个组合至少 3 次重复。
2. **防御适配**：如果目标模型有自适应防御，组合成功点可能随时间衰减，需持续轮换策略。
3. **成本估算**：每新增一个组合，对 5 个 PROBE 用例大约增加 5 次 API 调用；8 个组合约 40 次，加上 3 次重复约 120 次，按 GPT-4o 估算约 $0.5-2 USD。
4. **合规边界**：所有测试应在授权环境中进行，仅用于 Red Team / 安全评估目的。
