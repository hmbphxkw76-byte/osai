## 1. 架构概览

```
main.py (CLI 入口 & 任务编排)
  ├── converters.py   → 攻击策略转换器 (24个) & 攻击组合配置 (67组)
  ├── targets.py      → .env 配置加载 & Target 工厂 (自定义HTTP/OpenAI/Gemini/Claude)
  ├── engines.py      → 核心攻击引擎 (单轮/Crescendo多轮) & 实时仪表盘
  ├── reporter.py     → 热力图 + 终端报告 + 考试Markdown报告
  ├── utils.py        → results/ 目录管理
  └── data/loader.py  → JSON用例加载 + 从 data/payloads.py (唯一真相源) 提取Payload变量 + Pydantic校验
```

## 3. CLI 参数解析

### 3.1 完整参数表

| 参数 | 类型 | 默认值 | 说明 |

| `--auto-gate` | flag | `False` | 启用阶梯式门控执行 (PyRIT 最佳实践) |

| `--target-no-ssl` | flag | `True` | 跳过 SSL 证书验证 |
| `--target-verify-ssl` | flag | `False` | 验证 SSL 证书 |
| `--target-extra-headers` | str | `""` | 自定义 HTTP 请求头 (JSON 字符串) |

| `--env-file` | str | `.env` | .env 配置文件路径 |
| `--case` | str | `""` | 用例白名单 (逗号分隔) |

### 3.2 快捷别名

| 别名 | 含义 |
|------|------|
| `all-probe` | PROBE 阶段全部用例 |
| `all-single` | 单轮阶段全部用例 |
| `all-crescendo` | Crescendo 阶段全部用例 |
| `all-error` | 重跑上次结果为 ERROR 的用例 |

### 3.3 六种典型调用模式

## 4. 启动流程 10 步详解

### Step 0: 显示 CLI 参数
```
📋 执行参数: python main.py --lang cn --phase probe --concurrent 5 ...
```
将用户传入的所有参数拼接回显，便于复现。

### Step 1: 初始化 PyRIT + 创建 results 目录
```python
ensure_results_dir()                              # 创建 results/ 目录
db_path = results_path(f"ai300_memory_{ts}.duckdb")  # DuckDB 内存数据库
await initialize_pyrit_async(memory_db_type="SQLite", db_path=db_path)
```

**时机**: 必须在创建任何 `PromptTarget` 之前调用。

### Step 2: 加载 .env 配置
```python
attacker_config, scorer_config = load_env_config(args.env_file)
```

按优先级加载：
1. 使用 `python-dotenv` 加载平铺 `KEY=VALUE` 到 `os.environ`
2. 使用 `configparser` 读取 `[SECTION]` 专属配置
3. 每个平台节统一使用 `CHAT_MODEL` + `SCORER_MODEL` 双模型键

支持的平台: `ZHIPU`, `OPENAI`, `QWEN`, `DEEPSEEK`, `OLLAMA`, `MISTRAL`, `GOOGLE_GEMINI`, `ANTHROPIC` 等。

### Step 3: 模型配置校验
- **自定义 API 模式** (`--target-url`): 仅需 `SCORER_MODEL` 配置评分器
- **非自定义 API 模式**: `CHAT_MODEL` 和 `SCORER_MODEL` 都必须设置

### Step 4: 创建评分器 Target
```python
scorer_target = create_scorer_target(scorer_config)
```
- 使用独立评分器配置创建 `OpenAIChatTarget(temperature=0)`
- 支持与攻击者不同的模型/平台（解决低能力模型无法胜任 Judge 的问题）

### Step 5: 创建攻击目标 Target
```python
# 自定义 API 模式
attack_target = CustomHttpChatTarget(
    endpoint=args.target_url,
    api_key=..., model=..., temperature=0.9,
    verify_ssl=..., api_format=..., extra_headers=...,
    content_type=..., http_method=..., jwt_token=...,
)
# 或 .env 模式
attack_target = create_attack_target(env_config=attacker_config)
```

三种 Target 创建模式:
| 模式 | 条件 | Target 类型 |
|------|------|-------------|
| A | 未指定 `--target-url` | `OpenAIChatTarget` (PyRIT 原生) |
| B | 指定 `--target-url` | `CustomHttpChatTarget` (基于 requests) |
| C | `.env` 配置 Gemini/Claude | `CustomHttpChatTarget` (自动构造端点) |

### Step 6: 加载 Payload 变量
```python
_load_payload_vars(args)
```
加载优先级（由高到低）:
1. **Python 模块**: `data/payloads.py` (唯一真相源) → loader.py 按语言提取 — 主数据源
2. **Preset 预设**: 应用 `--payload-preset` 覆盖 (stealth/bruteforce/redteam/academic/minimal)
3. **动态注册**: 运行时 `register_payload()` 注入 (最高优先级，覆盖同名键)
4. **Pending JSON**: `results/` 下待入库的载荷兜底合并
5. **命令行覆盖**: `--payload-vars` JSON 字符串

### Step 7: 攻击特征库概况
```
🎯 攻击特征库: 24 个转换器 + 67 组攻击组合 (单层: XX | 双层: XX | 三层链: 17)
```

统计 `CONVERTER_MAP` 和 `GLOBAL_ATTACK_COMBINATIONS` 的数量分布。

### Step 8: 解析用例过滤
```python
case_filter = [x.strip() for x in args.case.split(",")]    # 白名单
exclude_filter = [x.strip() for x in args.exclude_case.split(",")]  # 排除
```
- 支持快捷别名 `all-probe` / `all-single` / `all-crescendo`
- `all-error`: 从最新日志中提取上次 ERROR 的 `(case_id, combo_name)` 精确对重跑

### Step 9: 确定测试用例文件
```python
DATA_DIR = "data"
json_filename = "test_cases_cn.json"  # 或 _en.json
json_file = os.path.join(DATA_DIR, json_filename)
```

### Step 10: 执行模式分发
```python
if args.auto_gate:
    await run_phased_campaign(...)    # 阶梯式门控
elif args.phase != "all":
    await run_campaign(phase_filter=args.phase, ...)   # 单阶段
else:
    await run_campaign(...)           # 全量
```

## 5. 三种执行模式

### 5.1 单阶段模式 (`--phase probe|single|crescendo`)

调用 `run_campaign()` 直接执行指定阶段的所有用例：

```python
await run_campaign(
    json_file=json_file,
    campaign_name="AI-300_PROBE_Recon",
    phase_filter=args.phase,    # 过滤用例
    attack_target=attack_target,
    scorer_target=scorer_target,
    case_filter=case_filter,
    exclude_filter=exclude_filter,
    combo_filter=_combo_filter, # all-error 精确对
)
```

**内部流程**:
1. `load_test_cases()` — 加载 JSON → Pydantic 校验
2. 阶段过滤 (`classify_case`) — 按 `PROBE_` 前缀/`multi_turn_objectives` 分类
3. 白名单/排除过滤 (`--case` / `--exclude-case`)
4. `combo_filter` 精确匹配 (all-error 专用)
5. 自动识别单轮/多轮用例 → 生成对应任务
6. 创建 `DashboardState` + `Progress` 实时仪表盘
7. 并发执行全部任务 (`asyncio.as_completed`)
8. 保存攻击日志 JSON → 生成热力图 → 打印终端报告 → 生成考试报告

### 5.2 阶梯式门控模式 (`--auto-gate`)

调用 `run_phased_campaign()` 分三个阶段串行执行，自动跳过低成功率阶段：

```
STAGE 1: PROBE 快速探测
  ├─ 成功率 ≥ gate_threshold → 进入 STAGE 2
  └─ 成功率 < gate_threshold  → ⚠️ 跳过单轮，直接进入 STAGE 3

STAGE 2: 单轮主力突破
  ├─ 成功率 ≥ gate_threshold → 进入 STAGE 3
  └─ 成功率 < gate_threshold  → ⚠️ 跳过 Crescendo

STAGE 3: Crescendo 攻坚
  └─ 使用多轮渐进式攻击进行深度突破
```

完成后合并所有阶段结果，生成综合报告。

### 5.3 全量模式 (`--phase all`)

调用 `run_campaign(phase_filter="all")`，不区分阶段，所有用例打一遍。向后兼容旧版本。

## 6. 攻击引擎核心机制

### 6.1 用例分类

```python
def classify_case(case: dict) -> str:
    if case_id.startswith("PROBE_"):
        return "probe"
    if "multi_turn_objectives" in case:
        return "crescendo"
    return "single"
```

### 6.2 单轮攻击引擎 (`execute_single_attack`)

1. 模板解析: `{key}` → `PAYLOAD_VARS[key]`
2. 创建 `CleanedSelfAskTrueFalseScorer` (防假阴性评分器)
3. 创建 `PromptNormalizer` + `PromptConverterConfiguration`
4. 预先应用转换器捕获实际 prompt（取证）
5. 发送 prompt → 获取响应 → 评分
6. 最多重试 3 次 (指数退避)
7. 返回结果字典 (含 case_id, combo_name, status, 攻击payload, 响应, 评分理由)

### 6.3 Crescendo 多轮攻击引擎 (`execute_crescendo_attack`)

1. 解析多轮 `multi_turn_objectives` 模板变量
2. 逐轮执行：
   - 应用全部转换器到当前轮 prompt
   - 直接发送到 target (PyRIT Message 格式)
   - 提取 assistant 响应
   - **每轮结束立即评分** — 一旦成功即停止
3. 每轮支持最多 3 次重试
4. 累计收集所有轮次响应文本（取证）
5. 返回结果字典 (含 success_turn, 全部轮次 prompts)

### 6.4 防假阴性评分器 (`CleanedSelfAskTrueFalseScorer`)

继承 `SelfAskTrueFalseScorer`，评分前自动清理模型响应：
- 剥离 Markdown 代码块标记
- 移除中英文免责声明行
- 移除转折式免责前缀
- 清理多余空行

### 6.5 实时仪表盘 (`DashboardState`)

使用 `rich.Live` 组件 4Hz 刷新，显示：
- 任务总数 / 进度条 / 耗时
- 🎯 成功数 / ❌ 失败数 / ⚠️ 错误数
- 最新攻击流日志

## 8. 数据流向图

```
CLI 参数 (main.py)
  │
  ├─→ .env 文件 (targets.py::load_env_config)
  │     ├─→ attacker_config (CHAT_MODEL)
  │     └─→ scorer_config  (SCORER_MODEL)
  │
  ├─→ data/payloads.py (唯一真相源, data/loader.py → 按语言提取)
  │     └─→ PAYLOAD_VARS (模板变量 {key})
  │
  ├─→ data/test_cases_{lang}.json (data/loader.py)
  │     ├─→ Pydantic 校验 (TestCaseSet)
  │     └─→ dict 列表 (向后兼容)
  │
  ├─→ converters.py
  │     ├─→ CONVERTER_MAP (24个转换器)
  │     └─→ GLOBAL_ATTACK_COMBINATIONS (67组攻击组合)
  │
  └─→ 执行引擎 (engines.py)
        ├─→ execute_single_attack()
        │     ├─→ 模板解析 {key} → PAYLOAD_VARS
        │     ├─→ 应用转换器
        │     ├─→ PromptNormalizer → Target
        │     └─→ CleanedSelfAskTrueFalseScorer
        │
        └─→ execute_crescendo_attack()
              ├─→ 逐轮转换 + 发送
              ├─→ 每轮结束即评分
              └─→ 累计全部响应

输出 (reporter.py)
  ├─→ results/*_log.json        (攻击日志)
  ├─→ results/*_heatmap.png     (热力图)
  ├─→ results/*_Exam_Report.md  (考试报告)
  └─→ results/*_memory.duckdb   (PyRIT 内存数据库)
```
