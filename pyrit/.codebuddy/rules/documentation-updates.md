# 文档更新规则 — 日期与版本管理

## 规则编号: DOC-001

**生效日期**: 2026-07-19
**优先级**: 强制（MUST）

---

## 规则正文

### 1. 文档头部必须包含元数据

所有 `docs/` 目录下的 Markdown 文档**必须**在文件顶部包含以下元数据块：

```markdown
# {文档标题}

> **最后更新**: YYYY-MM-DD
> **版本**: v{X.Y}
> **关联模块**: {模块名/路径}
> **状态**: 草稿 / 已完成 / 已归档
```

**示例**：
```markdown
# AI-300 框架架构设计

> **最后更新**: 2026-07-19
> **版本**: v3.5
> **关联模块**: pyrit_ai300/
> **状态**: 已完成
```

### 2. 日期格式标准

- **格式**: `YYYY-MM-DD`（ISO 8601 标准）
- **时区**: UTC+8（北京时间）
- **示例**: `2026-07-19`

**禁止**：
- ❌ 使用 `2026/7/19` 或 `July 19, 2026` 等非标准格式
- ❌ 使用相对日期（如"今天"、"昨天"）

### 3. 何时必须更新日期

以下场景**必须**更新文档的"最后更新"日期：

| 场景 | 需更新的文档 | 说明 |
|------|------------|------|
| 新增/修改代码模块 | `ARCHITECTURE.md` | 架构变更同步 |
| 新增/修改 CLI 参数 | `ARCHITECTURE.md` | CLI 命令参考同步 |
| 新增/修改载荷文件 | `payload_optimization_*.md` | 载荷库变更同步 |
| 新增/修改侦察逻辑 | `recon_optimization_*.md` | 侦察引擎变更同步 |
| 新增 REV-* 优化项 | 对应实施报告 + `architecture_review.md` | 优化状态同步 |
| 修改数据目录结构 | `ARCHITECTURE.md` §10 | 目录结构同步 |
| 修改评分器逻辑 | `ARCHITECTURE.md` §2.3 + §5 | 评分策略同步 |
| 修改报告生成逻辑 | `ARCHITECTURE.md` §9 | 报告结构同步 |

### 4. 版本号管理

文档版本号遵循语义化版本（SemVer）：

```
v{MAJOR}.{MINOR}
```

| 版本变更 | 触发条件 | 示例 |
|---------|---------|------|
| MAJOR (+1) | 架构重大重构、不兼容变更 | v3 → v4 |
| MINOR (+0.1) | 新功能、新模块、新优化项 | v3.4 → v3.5 |

### 5. 实施报告关联

每个 REV-* 优化项实施后，**必须**：

1. 创建/更新实施报告：`docs/rev{N}_implementation.md` 或 `docs/rev{N}_to_rev{M}_implementation.md`
2. 更新 `architecture_review.md` 中对应 GAP 的状态为 `✅ 已完成`
3. 更新 `ARCHITECTURE.md` 中的版本号和统计数据
4. 在实施报告底部添加关联文档链接

### 6. 文档间交叉引用

文档间的交叉引用**必须**使用相对路径：

```markdown
✅ 正确: [architecture_review.md](./architecture_review.md)
❌ 错误: [architecture_review.md](docs/architecture_review.md)
❌ 错误: [architecture_review.md](https://github.com/...)
```

### 7. 变更日志（可选）

对于频繁更新的文档，建议在文档末尾维护变更日志：

```markdown
## 变更日志

| 日期 | 版本 | 变更内容 |
|------|------|---------|
| 2026-07-19 | v3.5 | 新增 REV-3 至 REV-10 优化项集成 |
| 2026-07-19 | v3.4 | 完成 REV-1/REV-2 P0 闭环优化 |
| 2026-07-17 | v3.1 | 19 项侦察优化实施 |
```

## 检查清单

提交文档变更时，确认以下事项：

- [ ] 文档顶部包含 `> **最后更新**: YYYY-MM-DD` 元数据
- [ ] 日期格式为 `YYYY-MM-DD`
- [ ] 版本号已更新（如有功能变更）
- [ ] 关联文档已同步更新（如 `architecture_review.md` 状态）
- [ ] 交叉引用使用相对路径
- [ ] 新增优化项已创建实施报告
