## 流式侦察优化（Streaming Recon，2026-07-18）

### 背景
原侦察策略：3 个适配器（Garak + DeepTeam + ProtocolFingerprint）并行执行，但 `ReconEngine.run()` 等待全部完成后一次性合并。最慢工具（Garak 3-5分钟）决定总耗时。

优化目标：ProtocolFingerprint 先完成（~30s）→ 立即产出部分画像驱动攻击准备，Garak/DeepTeam 完成后 → 补充漏洞发现。

### 新增方法
- `ReconEngine.run_streaming()` — 生成器，每个适配器完成后立即 yield `(tool_name, partial_profile, is_complete)`
- `ProfileMerger.merge_incremental()` — 增量合并新结果到现有 TargetProfile
- `ProfileMerger._merge_fingerprint_incremental()` — 仅填充空字段
- `ProfileMerger._merge_vulnerabilities_incremental()` — 追加 + 去重
- `ProfileMerger._merge_surfaces_incremental()` — 追加去重

### 修改文件
- `pyrit_ai300/reconnaissance/recon_engine.py` — 新增 `run_streaming()` 生成器方法
- `pyrit_ai300/reconnaissance/profile_merger.py` — 新增 `merge_incremental()` + 3 个增量合并辅助方法
- `pyrit_ai300/cli.py` — `--auto-recon` 使用流式模式，打印每个工具完成进度
- `pyrit_ai300/tests/test_recon/test_recon_engine.py` — 新增 `TestReconEngineStreaming` 类（3 个测试）
- `pyrit_ai300/tests/test_recon/test_profile_merger.py` — 新增 `TestProfileMergerIncremental` 类（7 个测试）

### 架构
```
ProtocolFingerprint (30s) ──→ yield partial_profile ──→ 可立即开始攻击准备
Garak (3-5min) ──→ yield partial_profile ──→ 补充漏洞发现
DeepTeam (1-2min) ──→ yield final_profile ──→ 完整画像
```

## OWASP 冲突解决机制（2026-07-18 续）

### 背景
原 ProfileMerger 按 `category + description[:50]` 去重，导致 Garak 报 `prompt_injection` 和 DeepTeam 报 `jailbreak`（都映射到 LLM01）被当作两个独立漏洞。需要统一到 OWASP ID 做分类键，实现真正的交叉验证。

### 新增文件
- `pyrit_ai300/reconnaissance/owasp_taxonomy.py` — 统一 OWASP 分类映射器
  - `GARAK_TO_OWASP` / `DEEPTEAM_TO_OWASP` / `PROTOCOL_TO_OWASP` — 工具原始 category → OWASP ID 映射
  - `KEYWORD_TO_OWASP` — 兜底关键词匹配
  - `OWASP_PROBE_FAMILY_MAP` — OWASP ID → 攻击探针族映射
  - `OwaspTaxonomy.normalize()` — 将原始 category 映射到 OWASP ID
  - `OwaspTaxonomy.resolve_conflict()` — 同一 OWASP ID 多工具发现的冲突解决
    - 严重等级差异 ≥ 2 级 → 标记 `conflict: true`
    - 多工具一致发现 → 置信度 +0.10（上限 0.95）
    - 冲突时取最高严重等级 + 最高置信度

## AIMAP → Garak 顺序侦察（2026-07-18 续）

### 背景
原流程：用户输入 URL → Garak 直接扫描（硬编码 openai/gpt-4o，盲扫浪费）
新流程：AIMAP 协议识别 → 提取可探测端点 → 用户选择 → Garak 用检测结果配置

### 新增方法
- `ReconEngine.extract_garak_endpoints(aimap_result)` — 从 AIMAP 结果提取 Garak 可探测端点
  - 协议 → Garak model_type 映射（ollama→ollama, vllm/openwebui→openai）
  - 自动填充 model_name（从 AIMAP 提取或默认值）
  - 返回端点列表（url/protocol/model_type/model_name/label）

### 修改文件
- `pyrit_ai300/cli.py` — `_run_wizard_recon()` 重构为三步向导：
  1. 选择目标（菜单或手动输入）
  2. AIMAP 协议识别 → 显示可探测端点菜单 → 用户选择
  3. 确认并执行（Garak 使用 AIMAP 检测的端点/模型配置）
- 支持跳过 Garak（仅用 AIMAP 结果）
- AIMAP 失败时降级为 Garak 自动检测
