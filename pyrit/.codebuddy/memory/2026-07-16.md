## Detailed Findings 报告格式优化（v4 - 标题格式 + 证据原始性）

### 问题
用户反复指出 Detailed Findings 格式不符合要求。经过仔细对比实际输出和参考格式，发现以下关键偏差：
1. **标题**：使用原始攻击名（如 `LLM01:2024 — Prompt Injection Direct`），而非 `{简洁描述}: {攻击面}` 格式
2. **描述**：包含模块名（太长），参考是简洁独立的描述
3. **证据**：截断300字符且有 `[Payload]`/`[Response]` 前缀，参考是原始完整响应
4. **攻击面**：未在标题中显示，参考在标题中显示

### 修复内容
1. **新增 `_generate_title()` 方法**：
   - 从 category 映射到简洁中文标题（如 `embedding_info_leakage` → `嵌入系统信息泄露`）
   - 标题与 Description 分离：Title 是极简短语，Description 是完整句子

2. **更新 `_generate_description()` 方法**：
   - 移除所有描述中的模块名引用（如 `f"直接提示注入攻击成功绕过 {module_name} 的安全控制..."`）
   - 描述保持简洁独立

3. **更新 `_extract_evidence()` 方法**：
   - 移除 300 字符截断逻辑
   - 移除 `[Payload]`/`[Response]`/`[Blocked]` 前缀
   - 返回原始响应数据，保持证据完整性
   - 最多返回 3 个成功样本

4. **更新 `_extract_surfaces()` 方法**：
   - 更细粒度的攻击面推断映射（如 `embedding` → `["embedding", "embed"]`）
   - 优先级：攻击元数据 → 攻击名称推断 → 模块级回退

5. **更新 `_detailed_findings()` 方法**：
   - 标题格式改为 `{title}: {surfaces}`（如 `嵌入系统信息泄露: embedding, embed`）

6. **新增测试**：
   - `test_generate_title` — 验证标题生成
   - 更新 `test_detailed_findings_format` — 验证新标题格式和证据格式
   - 更新 `test_extract_surfaces_from_attack` — 验证细粒度 surfaces 推断

### 验证结果
- **105 tests passed**（100 + 5 新增）
- ruff check 通过
- 输出格式完全对齐用户提供的最佳实践示例

### 关键设计决策
- Title 和 Description 分离：Title 是极简短语（2-10字），Description 是完整句子
- 证据保持原始性：不截断、不加前缀，确保红队评估证据的可信度
- 攻击面推断：基于攻击名称关键词映射到具体攻击面（如 embedding → embedding, embed）
