# remediation/ — 整改中心（Remediation Center）

> **定位**：独立于 `specs/` 规约金字塔的专项整改层。
> **效力**：代码审计发现的 P0/P1/P2 问题的权威登记处与整改验收标准。
> **读者**：实施整改任务的 AI（必读）、评审 diff 的人工/AI。
> **版本**：v1.0（2026-09-06 首次全面代码审计）

---

## 与 specs/ 规约金字塔的关系

```
specs/                    本目录 remediation/
─────────────────────────────────────────────────
L0  宪法（C1-C12）            整改任务必须声明违反的宪法条款
L1  蓝图（I1-I10）            整改任务必须声明违反的不变量
L2  需求（REQ-xxx）           整改任务必须关联对应的 REQ ID
L3  任务协议                  整改任务的执行协议（八步协议）
L4  护栏（R-L/R-H/R-S）       整改任务的验收门禁
```

**交叉引用规则**：
- 本目录每条整改项必须引用 `specs/` 中的 REQ ID + 宪法条款 + 不变量（如：`REQ-114 / C2 / I4`）
- `specs/README.md保留指向本目录的链接
- 整改任务完成后必须同步更新 `specs/20-REQUIREMENTS.md` 和 `backlog.md`

## 整改任务标准动线

1. **立项**：审计项 → `backlog.md的 BL-xxx 登记 → 生成 TASK-xxx
2. **执行**：按 `specs/30-TASKS.md` 八步协议执行，落点声明必须关联 REQ ID
3. **验收**：按审计项对应的"整改验收标准"逐项勾选
4. **闭环**：关闭审计项 → 更新 `specs/20-REQUIREMENTS.md` 状态 → 同步 `backlog.md`
