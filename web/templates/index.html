🚀 六阶段管道概览

RedTeam_AI 是一套完整的 AI 红队自动化攻击管道，覆盖从目标侦察到报告生成的全流程：

L0 目标侦察 → L1 Garak → L2 桥接映射 → L3 Promptfoo → L4 PyRIT → L5 报告

当前已实现 L0 前置侦察：使用 Playwright 驱动浏览器，对目标 Web/AI 应用进行全自动侦测，生成 target_profile.json 文件。

支持：SPA 渲染 · API 端点发现 · 认证流程自动化 · Chat 端点推断 · 字典扫描

L0 — 目标侦察

简化两步走：先基本探测，再针对性深度侦察

输入一个或多个目标 URL，系统会先执行轻量 HTTP 探测，列出存活端点和认证需求，再决定下一步侦察策略。

🚀 基本探测说明
该阶段不携带认证信息，仅对常见 AI/Web 端点（如 /login、/v1/chat/completions、/api/tags 等）执行轻量 GET/POST 探测，返回状态码与响应摘要。

三档速率模式（统一超时 20 秒）：
  • stealth（隐身）：单请求串行 + 随机延迟 200-600ms，最大限度降低 WAF/IDS 触发概率，适合高防御站点。
  • balanced（平衡）：3 并发 + 50-150ms 延迟，兼顾速度与隐蔽性。
  • fast（快速）：5 并发 + 0-50ms 延迟，追求探测速度，可能触发频率限制。

使用组件：
httpx 根路径探测 → DictScanner（字典路径扫描器）→ EndpointInferrer（端点分类器：chat/auth/models/health/api） → WAF 关键词正则匹配（Cloudflare/Akamai/Imperva 等） → 速率限制提取（解析 x-ratelimit-* / Retry-After / 429 端点）

速率限制三档攻速建议：
  • P0 · 严格限速：窗口配额 ≤10 次或 Retry-After > 10s，必须用 stealth 单线程串行，攻击时需大幅降速。
  • P1 · 适度限制：窗口配额 ≤60 次或仅检测到限速头，推荐 balanced，攻击时需控制并发。
  • P2 · 宽松限制：窗口配额 >60 次，可使用 balanced/fast，攻击时可适度放宽。

三种后续分支：
  • 需要认证：探测到 /login、401/403 等，将提示填写 Cookie / API Key / JWT。
  • 无需认证：可直接启动深度侦察，无需额外认证参数。
  • 结果为空 / 反爬：将切换到高级探测模式，提供 stealth、手动登录、storageState 等参数。
💡 商业 AI 平台（千问、Kimi、ChatGPT 等）通常需要先获取 Cookie 再执行深度侦察。探出的速率限制值将直接影响后续攻击阶段的并发和频率设置。

⚙️ 功能开关
⚙️ 开关详解：
  • 启用字典扫描 — 用 200+ 条 LLM/Web 路径并发探测目标。耗时长但覆盖全，内网授权环境强烈建议开启
  • 显示浏览器窗口 — 关闭无头模式，弹真实 Chromium 窗口。方便调试登录流程，CI/批量时关闭
  • 禁用 SPA 渲染 — 不启动浏览器（纯 HTTP）。适用于 Ollama/纯 API 服务，速度极快
  • 禁用 JS 提取 — 不下载分析 JS bundle。会丢失动态路由和隐藏端点，一般不勾
  • 禁用流量捕获 — 不监听浏览器网络请求。Chat 端点推断将失效，不要勾
  • 验证 SSL 证书 — 校验目标证书。自签名证书（内网常见）会报错，公网目标建议勾选
💡 推荐 4 种配置：
① 基本探测（Ollama/纯 API）：勾「字典扫描」+「禁用 SPA 渲染」
② 标准 SPA（默认）：勾「字典扫描」
③ 调试登录：勾「字典扫描」+「显示浏览器」
④ 静默外网：勾「验证 SSL」，其余默认
🔧 高级参数
🔧 探测速率详解：
  • 🕵️ 隐身模式 (stealth) — 单请求串行 + 200~500ms 随机抖动，~12 RPM。生产/外网目标强烈推荐，几乎不触发 WAF/IDS 行为检测
  • ⚖️ 平衡模式 (balanced) — 2 并发 + 50~150ms 抖动，~30 RPM。内网/授权测试环境适用
  • ⚡ 快速模式 (fast) — 5 并发 + 微量延迟，~60 RPM。仅在内网隔离环境或明确授权快速扫描时使用
💡 企业红队最佳实践：默认使用 stealth 模式（1 并发 + 随机抖动）可确保不被目标行为检测发现。 即使开启字典扫描（600+ 路径），stealth 模式也能在约 5-10 分钟内完成，无需担心速度问题。
🎯 目标参数
🎯 目标 URL — AI Recon 的侦察入口，引擎会通过 6 个阶段 自动化分析目标：
① HTTP 基线探测（httpx）→ ② 认证流程 → ③ SPA 浏览器渲染（Playwright）→ ④ 端点枚举（字典）→ ⑤ Chat 端点推断 → ⑥ 组装输出

支持的目标类型：
  • AI API 服务：Ollama (http://localhost:11434)、vLLM、LocalAI、OpenAI 兼容服务
  • Web 应用 + AI：含 Chat 界面的 SPA 应用（React/Vue/Next.js）
  • 内网靶机：自签名证书的 HTTPS 服务（需关闭"验证 SSL 证书"）
💡 如果不确定目标类型，保持默认配置启动一次基本探测即可。
🔐 认证参数（可选）
支持 Playwright storageState.json / 纯 Cookie 字符串 / Netscape cookies.txt。上传后会自动恢复 cookies + localStorage + sessionStorage。
🔐 认证叠加策略：所有填写的认证方式会 同时生效（叠加发送）——Cookie、Bearer Token、API Key 会同时携带。如需单一认证方式，请只填写一个字段。

7 种认证方式 + 14+ 种组合场景：
  • 表单登录：填写 登录页面 URL + 登录凭据 JSON，引擎自动检测用户名/密码输入框并提交
  • Cookie 注入：跳过登录页，直接注入 Cookie（从开发者工具复制 session=abc123）
  • Bearer Token (JWT)：注入 Authorization: Bearer eyJ... 头（JWT/API Token 通用）
  • API Key：注入自定义 Header，如 X-API-Key: sk-xxx 或 Authorization: Bearer sk-xxx
  • 额外请求头：JSON 格式注入任意 Header，如 CSRF Token、自定义认证头
  • Cookie + API Key 组合：AI 应用高频场景（Session 鉴权 + API 认证双层）
  • 无需认证：全部留空，引擎对公开端点进行匿名探测

🧭 实战工作流：从登录到深度攻击

针对需要登录认证的 AI Web 应用（如千问、Kimi、Dify、企业内网 AI 助手），推荐以下四步实战流程。点击上方按钮查看完整步骤。

📋 四步完整工作流
1
获取 Cookie → 转换为 storageState

在浏览器中登录目标 AI 应用后，打开 DevTools (F12) → Network 标签，找到任一 API 请求，右键选择 Copy as cURL (bash)，然后使用工具转换：

python tools/cookie_to_authfile.py -o qianwen_auth.txt

💡 交互式粘贴，支持 Copy as cURL / Copy request headers / 纯 Cookie 字符串三种格式自动识别。--storage-state 会自动识别为 Playwright storageState / 纯 Cookie / Netscape cookies.txt。

2
L0 前置侦察（带 Cookie 认证）

在 Web UI 的 storageState 会话文件 区域上传生成的文件，或通过命令行执行：

python recon/main.py --target https://www.qianwen.com --storage-state qianwen_auth.txt --har-output outputs/traffic.har

引擎将自动：① 浏览器渲染 SPA → ② 捕获 XHR/fetch 请求 → ③ 识别 Chat API 端点 → ④ 推断认证机制 → ⑤ 生成 target_profile.json

⚠️ 如遇反爬（滑块/Cloudflare）：评估是否使用 --stealth patchright 或 --stealth playwright_stealth。 商业 AI 平台通常有 Bot 检测，可能需要手动处理验证码后再导出 Cookie。
3
Cookie 过期处理 — 自动登录（可选）

如果 Cookie 频繁过期（通常 15-30 分钟），可在 Web UI 填写登录凭据实现自动登录：

登录页面 URL: https://www.qianwen.com/login
登录凭据: {"username":"your_account","password":"your_pwd"}

引擎将在每次扫描前自动执行登录流程，无需手动刷新 Cookie。支持表单登录和 SSO 跳转识别。

4
L1-L4 全流程攻击（从侦察结果到深度对抗）

获取 target_profile.json 后，执行完整攻击管道：

python pipeline.py --target https://www.qianwen.com --stage recon
python pipeline.py --target https://www.qianwen.com --stage garak
python pipeline.py --target https://www.qianwen.com --stage pyrit

管道自动执行：L1 Garak 模型漏洞探测 → L2 Bridge 攻击种子映射 → L3 Promptfoo 模板生成 → L4 PyRIT 深度攻击（Crescendo 多轮越狱 + 编码绕过 + 自适应攻击）→ L5 统一报告

💡 最佳实践： ① 首次侦察用 stealth 速率避免触发 WAF ② 侦察结果中的 chat_api_url 是后续攻击的入口 ③ 国内商业 AI 平台建议先手动登录获取 Cookie 再执行自动侦察 ④ 自建/内网 AI 应用可直接填登录凭据实现全自动流程
❓ 常见问题速查
问题 原因 解决方案
Cookie 太长命令行报错 Windows CMD/PowerShell 命令长度上限 ~8191 字符 使用 cookie_to_authfile.py 转换后，通过 storageState 文件传入（CLI 用 --storage-state，Web UI 上传文件），避免在命令行或 Cookie 注入框粘贴长字符串
侦察 401/403 未授权 Cookie 过期，或缺少 CSRF Token / localStorage / sessionStorage 重新登录后导出完整浏览器状态，使用 --storage-state 恢复 cookies + localStorage + sessionStorage；或用 --manual-login 在 headed 模式下手动完成 MFA/验证码后自动保存 storageState
storageState 加载失败 / 格式错误 文件路径不存在、格式不被识别，或 Playwright 版本与 storageState 不兼容 确保文件为 storageState.json / 纯 Cookie 字符串 / Netscape cookies.txt 之一；检查文件是否已上传/存在；必要时用 --manual-login 重新导出
HAR 文件为空 / 未生成 禁用了流量捕获，或浏览器上下文关闭前未刷新/导航页面 不要勾选 禁用流量捕获；确保目标页面已加载并触发 XHR/fetch 请求；HAR 在扫描正常结束时自动写入 outputs/traffic_*.har
浏览器自动化触发验证码 目标站点有反爬/Bot 检测机制 勾选 显示浏览器窗口 + 手动登录，完成验证后自动保存 storageState；或在 CLI 使用 --stealth patchright / --stealth playwright_stealth
Chat API 端点未发现 SPA 渲染或流量捕获未生效 确保未勾选 禁用 SPA 渲染 和 禁用流量捕获；开启 HAR 录制 后手动在 Chrome DevTools 中打开 HAR 文件查找 /chat 或 /api/ 请求
haralyzer 离线分析报错 可选依赖未安装 安装分析库：pip install haralyzer；也可直接用 Chrome DevTools / harviewer 查看 HAR
SSL 证书错误 内网自签名证书未信任 不勾选 验证 SSL 证书，或上传企业 CA 证书 .pem 文件
