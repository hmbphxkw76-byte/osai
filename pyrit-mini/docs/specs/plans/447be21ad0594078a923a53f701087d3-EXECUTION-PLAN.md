## 1. 目标与非目标

### 1.1 目标（Goals）

| # | 目标 | 可度量判据 |
|---|------|-----------|
| G1 | 输入层支持企业真实目标（认证态/多步会话/多协议/多租户） | 5 类 mock 靶标全部可被完整攻击，含需登录 + 需 chat_id 场景 |
| G2 | 侦察输出为攻击面图谱（多标签+置信度+信任边界） | 靶场组件识别准确率分组件可断言；未知目标可降级到通用路径 |
| G3 | 攻击为有状态多步链（含验证与清理） | RAG 投毒 / MCP 枚举调用两条链端到端成功且 cleanup 生效 |
| G4 | 判定为影响链而非"输出有害" | 报告中出现能力→动作→影响三元组 + 外传验真回执 |
| G5 | 交付物可复现、可脱敏、可回归 | PoC 独立可跑率 100%；密钥剥离 0 遗漏；CI 全绿 |

### 1.2 非目标（Non-Goals）

- ❌ 服务化 / Web 平台 / 多用户 / 任务队列（定调：单机 CLI）
- ❌ 向量库直连投毒、微调后门（沿用"黑盒 HTTP 不可测试"裁决，REQ-110/131 已移除）
- ❌ 引入 FastAPI/Flask 等新运行时依赖（mock 靶场用标准库 `http.server`，NEG-4）
- ❌ 替换 PyRIT 原生攻击组件（C1：原生优先，自研仅限 Glue/适配/输出）

### 1.3 三个必须纠正的架构级误配（本方案存在理由）

| # | 现状形状 | 企业真实形状 | 不改的后果 |
|---|---------|-------------|-----------|
| A | 输入 = URL / burp.txt（无状态单请求） | 认证态 + 多步会话 + 流式/多协议 + 多租户 | 每接一个目标补一次认证/会话代码，适配器散落，后期全面重写 |
| B | 侦察输出 = 单标签 `MCP/A2A/RAG/Agent/Model` | 攻击面图谱：多标签 + 置信度 + 信任边界 + 数据流边 | 组合链攻击（间接注入→工具调用→数据外传）无法表达 |
| C | 成功判据 = ASR（模型是否说坏话） | 影响链：能力 → 动作 → 影响（含外传/副作用实证） | 报告写不出"危害成立"，交付物被判定无效 |

## 3. 六大核心抽象：契约与落点

### 3.1 EventLog（一切派生之源）

```python
# core/events.py
@dataclass(frozen=True)
class Event:
    ts: float; run_id: str; phase: str   # recon|arm|strike|assess|report
    node_id: str | None                   # SurfaceGraph 节点 / playbook step
    etype: str                            # probe|detect|seed_selected|attack_sent|
                                          # response|verdict|impact|evidence|cleanup|error
    payload: dict; refs: dict             # {seed_id, conv_id, step_id, evidence_id}
```

- 落盘：`outputs/<run_id>/events.jsonl`（append-only，崩溃不丢）
- 消费者：终端（`utils/display.py`）、报告（`report/generator.py`）、证据（`report/evidence.py`）、回放/续跑（`strike/playbook/state.py`）
- **硬规则**：阶段层只写事件，禁止阶段间直接读对方内存结构（衔接蓝图 2.2 与 NEG-3）

### 3.2 TargetAdapter

```python
class TargetAdapter(Protocol):
    protocol: str                       # http|sse|ws|jsonrpc|multipart|browser
    async def send(self, req: AdapterRequest) -> AdapterResponse: ...
    async def close(self) -> None: ...
    def describe(self) -> dict          # 供 SurfaceGraph 消费
```

`AdapterRequest{method,url,headers,body,auth,session_state,stream}`
认证态（Bearer/Cookie/OAuth/mTLS）、会话态（chat_id/thread_id）、流式（SSE 增量拼接）全部在 adapter 内部，**编排层不可见协议差异**。

### 3.3 SurfaceGraph

```yaml
nodes:
  - id: n1
    labels: [mcp]                 # 多标签，非单值
    confidence: {mcp: 0.92, agent: 0.61}
    capabilities: [tools_list, tools_call, resources]
    evidence: [event_id...]       # 可回溯到 EventLog
edges:
  - from: n_gateway; to: n1; type: data_flow; trust_boundary: true
unknown:
  fallback_labels: [model]       # 识别失败兜底
```

- 兼容：`recon/surface/legacy.py` 导出旧 `target_fingerprint` 视图，W5 删除

### 3.4 PlaybookEngine（攻击链）

```yaml
# strike/playbook/playbooks/rag_poison.yaml
id: rag_poison
target_labels: [rag]
steps:
  - id: write
    action: upload_document
    params: {template: poison_doc, canary: true}
    verifier: {type: http_status, expect: 200}
    cleanup: {action: delete_document, ref: write.doc_id}
  - id: trigger
    depends_on: [write]
    action: prompt
    params: {seed_set: rag_retrieval_trigger}
    verifier: {type: contains, field: citations}
  - id: verify
    depends_on: [trigger]
    action: verify
    params: {impact: poisoned_doc_influenced_output, exfil: markdown_image}
    on_fail: {next: null, verdict: not_reproduced}
```

- 每步必填 `verifier`；产生副作用必填 `cleanup`（无 cleanup 的 step 在 dry-run 之外禁止执行）
- 状态存 EventLog → 支持 `--resume <run_id>` 断点续跑

### 3.5 ImpactChain + ExfilChannel

```python
ImpactChain(capability, action, impact, evidence_ids, reproducible: bool)
ExfilChannel(kind=markdown_image|tool_param|url_param|callback, canary, oob_receipt)
```

- 一期只实现 3 类外传信道（markdown_image / tool_param / callback）+ 1 类副作用验证
- **判定规则**：无 ImpactChain 或 Exfil 回执的成功 → 降级记为 `content_only`（不计入 confirmed，报告单列）

### 3.6 ComponentRegistry + 声明式矩阵

```yaml
# config/components/mcp.yaml
labels: [mcp]
detect: {signals: [...], min_confidence: 0.6}
recon: [recon.mcp.enum_tools, recon.mcp.schema_extract]
seeds: [data/seeds/mcp/*]
converters: [json_rpc_wrap, base64, unicode_tag]
playbooks: [mcp_enum_call, mcp_tool_chaining]
scorer: mcp_tool_poisoning
report_section: report.component_reports.mcp
cleanup: [unregister_tool, restore_schema]
```

**护栏**：`tools/guard_extended.py` 新增规则 —— 编排层（`core/phases/`、`strike/common/dispatcher.py`）出现字面量 `"mcp"/"a2a"/"rag"` 即 BLOCKING。

## 4. 组件矩阵（9 类，一期）

| 组件 | 识别信号 | 专项侦察 | 攻击链形状 | 成立判据 |
|------|---------|---------|-----------|---------|
| Model | `/v1/chat`、`choices[].message`、system prompt 泄露 | 模型族/版本/护栏位置 | 单轮多路径 → 升级链 | 护栏绕过 + 系统提示/训练数据泄露 |
| Agent | `tools[]`/`functions[]`/`tool_calls` | 工具 Schema、权限边界、确认点 | 诱导→工具调用→副作用验证 | 越权工具调用 / 未确认执行 / 参数越界 |
| MCP | `/.well-known/mcp`、`tools/list`、`jsonrpc:2.0` | 工具枚举+Schema+资源面+来源 | 枚举→投毒→调用→外传验证 | 未授权工具执行 / Schema 投毒被采纳 |
| A2A | `/.well-known/agent.json`、`tasks/send` | AgentCard + 拓扑 + 信任链 | 发现→伪造→跨 agent 注入→劫持 | 伪造 agent 被信任 / 跨 agent 指令生效 |
| RAG | `/retrieve`、context 回显、引用标注 | 知识库边界、分块、重排 | 投毒→触发→验证被引用 | 投毒影响结论 / 跨租户泄漏（IDOR） |
| Multimodal/Upload | `/upload`、multipart、文档处理端点 | 载体白名单、解析/渲染链路 | 构造→上传→触发→验证 | 载体注入生效 / 渲染导致指令执行 |
| Memory/Session/Tenant | `chat_id`/`thread_id`/`memor`、`/history` | 记忆写入点、会话绑定、租户键 | 污染→新会话触发→验证持久化 | 跨会话生效 / 跨租户越权读取 |
| WebInfra | 网关头、401/429、JWT、审计回显 | 认证模型、限流、缓存键、日志点 | 单点攻击 + 成本放大 DoW | 认证绕过 / 限流失效 / 日志注入 / 成本放大 |
| SupplyChain（侦察级） | MCP server 来源、插件市场、模型卡片 | SBOM/依赖/权重清单（不引入依赖） | 不出攻击链，仅风险清单 | 不计入 ASR 分母 |

> **横切判据**：`ExfilChannel` + `ImpactChain` 不属于任何组件，所有组件的"成立"最终落到二者之一。
