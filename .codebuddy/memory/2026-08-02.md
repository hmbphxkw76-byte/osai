### 删除的规则（2 条）
- **原 G-069**（单一职责 + 函数 ≤50 行硬限制）：Python 社区共识是"函数应该短"，但不应设硬性行数限制。复杂但清晰的函数（如状态机、协议解析）可能超过 50 行仍是良好实践。

### 微调的规则（3 条）
- **G-081**（内存管理/流式处理）：从"避免一次性加载到内存"改为"优先使用生成器/迭代器；但需权衡可读性，简单场景不强制"——与 `pathlib.Path.read_text()` 等便利 API 兼容。
- **G-082**（原 G-083 先正确后优化）：改为"可读性优先于微优化；通过 profiling 定位实际瓶颈"——更符合 Python 之禅"Readability counts"。
- **G-099**（原 G-100 PR ≤400 行）：从"必须"改为"建议"，增加"功能完整性优先于硬性行数限制"——避免为满足行数限制而拆分出不完整的 PR。
