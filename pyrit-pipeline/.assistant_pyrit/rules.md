# PyRIT 项目规则

> AI 红队评估: ASR 驱动, 攻击为王, PyRIT 原生优先。
> 继承全局规则 G-001~G-125。以下为项目专项规则, 补充细化, 不得冲突。

---

## R-001 · ASR 数据驱动 + 攻击为王

攻击效果 (ASR 提升) 是第一优先级, 优先于代码美观、覆盖率、性能。
所有策略选择、场景路由、技术组合以 **ASR 实测数据** 为核心驱动, 不得凭直觉判断。
攻击效果与代码质量冲突时, 优先保证攻击效果。

## R-002 · PyRIT 原生框架优先 + 自研即增强

> 统领原 R-003/R-010, 适用于三库全部代码

1. **原生优先** — PyRIT 原生组件 (converter/executor/scorer/scenario/prompt_target/memory) 是首选
2. **自研即增强** — 自研代码必须至少组合或依赖一个原生组件, 不替代不绕过
3. **最佳实践对齐** — async 后缀命名 + keyword-only 参数 + 完整类型注解 + 原生注册表 + 原生配置 + 原生生命周期

## R-003 · 对齐 L5 专家水平

- 攻击链路覆盖 OWASP LLM Top 10 + Agentic Security
- 评分器校准, ASR 数据可信
- 代码符合 PyRIT 原生编码规范
- 输出报告可追溯, 证据链完整

## R-004 · 研究资料优先级 (理论先行)

1. **arxiv.org 学术文献** — 标注 arXiv 编号, 确保理论支撑
2. **GitHub 高 star/官方源码** — PyRIT/garak/Microsoft AI Red Team, 关注论文对应
3. **自行搜索** — 仅兜底, 须交叉验证

核心文献: PyRIT [arXiv:2407.01232] | JailbreakBench [arXiv:2402.01135] | HarmBench [arXiv:2402.04249] | Crescendo [arXiv:2404.01833] | TAP [arXiv:2312.02191] | PAIR [arXiv:2310.08437]

## R-005 · 运行后清理 + UTF-8 编码

> 合并原 R-008/R-012, 三库统一

- 运行后+异常退出: 递归清理 `__pycache__` + `.pyc` + `.pytest_cache`, 静默执行
- 运行前不清理 — Python 通过 mtime+size 校验自动管理缓存失效, 避免每次全量重编译 PyRIT 611 个文件的开销 (~8s)
- 所有文件 UTF-8 读写, 运行前设 `PYTHONIOENCODING=utf-8`
- 报告文件保留, 不受清理影响

## R-006 · 代码改动后: 全量测试 + L5 差距分析

> 合并原 R-009/R-015/R-021, 取代 R-011 端到端自动运行要求

1. **全量测试 (自动)** — `make check-full` (ruff check pipeline/ scripts/ tests/ conftest.py + pytest tests/), 零违规 + 0 failed
2. **PyRIT 1.0.1 一致性** — 不引入不兼容 API
3. **L5 差距分析 (自动)** — 改动前后对比 + 根因 + 优化方案, 更新到 `docs/l5_gap_analysis.md`
4. **端到端运行 (需确认)** — 不主动运行 `python main.py`, 除非用户确认

## R-007 · 方案确认前: L5 差距分析 + 用户确认

方案优化后必须: 输出方案概述 → L5 差距分析 (对比表+根因+学术依据) → 100% 对齐方案 → **等待用户确认后才改代码**。

## R-008 · 端到端验证: 自动追踪 + 验证后清理

> 合并原 R-023 + 新增 R-024

```
L5 差距分析发现端到端验证型差距
  ├─→ 1. 自动写入记忆库 (差距描述+触发条件+预期结果)
  ├─→ 2. 等待用户确认运行 (遵循 R-006 步骤 4)
  ├─→ 3. 运行后自动对齐 (验证每项 ✅/⚠️/❌, 更新 l5_gap_analysis.md)
  ├─→ 4. 验证通过的记忆条目自动删除 (R-024)
  └─→ 5. 如有新差距, 给出优化方案 (遵循 R-007)
```

**R-024 细则**: 端到端验证通过的记忆条目自动从记忆库删除。已验证的修复已沉淀在 git 历史 + `docs/l5_gap_analysis.md` 中, 记忆库仅保留未验证待办和活跃规则, 避免信息过载。

## R-009 · 工程规范

> 合并原 R-005/R-006/R-013/R-018

- **分级测试**: 单模块→单元测试, 模块间→集成测试, 多模块→回归测试
- **文档时间标记**: 更新 .md 时添加 `YYYY-M-D` 时间标记
- **Makefile 同步**: scripts/*.py 自动可用 `make script-<name>`, 高频脚本注册独立 target
- **实施前检查清单**: 方案确认后执行 (受影响文件/依赖/配置/测试/文档/规则合规/记忆库), 每项标注 ✅/⚠️/➖
